The most common bug I find in AI-built apps isn't what you'd think.

It's that there's no real difference between a normal user and an admin.

The login works. The dashboard loads. It demos great. Then someone changes an ID in a request and they're looking at data that was never theirs.

And that's how it is in a lot of products. On a fintech tool I worked on, one small business seeing another's financials would be a disaster. On a creator marketplace, no creator should see what another creator earned. "Who can see what" isn't a detail; it's the product.

It's not a rare mistake, either. A security firm recently scanned 380,000 vibe-coded apps and found ~5,000 leaking sensitive data: medical, financial, internal company info. A lot of it just sitting there, public by default.

It happens because AI writes the happy path. "Let users log in and see their stuff" is easy. "Make absolutely sure they can only see their stuff" is the boring, invisible 30%. And it's invisible exactly when it matters: nothing breaks in the demo. It breaks the day a real user, or a curious one, changes a number in the URL.

When I audit these, I check the same short list every time:
- authentication AND authorization (can a normal user reach admin routes?)
- row-level security on every table, not just the obvious ones
- secrets that aren't sitting in the frontend
- rate limits, and the edge cases real users create

I found 14 of these in a hospitality app's Supabase recently, including booking records any logged-in user could read, not just their own.

If you've built something with AI and haven't had eyes on that list: what's the one thing you're least sure about? Reply and I'll tell you how I'd check it.
