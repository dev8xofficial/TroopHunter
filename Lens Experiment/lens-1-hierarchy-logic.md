## Step 1 — Full Element Inventory

Read all component files for the target screen. List every distinct text
or visual element you can identify. For each, record:
  - Element description (what it renders visually, not semantically)
  - Size (from typography token or Tailwind class, in px)
  - Weight (from typography token or Tailwind class, 100–900)
  - Color (hex from tokens — cross-reference with tokens.md)
  - Position in the component hierarchy (which component, where in the layout)
  - Whether it appears across multiple components or in one only

Do not rank yet. Do not filter. Capture everything, including small
labels, metadata text, and micro-elements.

## Step 2 — Dominance Ranking

Now rank the elements from Step 1 by visual dominance — the order in
which the eye would be drawn to them based on the code's visual properties.

For each rank position, identify:
  - Which element(s) occupy this level
  - WHY they dominate at this level — be specific:
      Is it SIZE alone? SIZE + WEIGHT? ISOLATION? COLOR CONTRAST?
      SPATIAL POSITIONING? Or a combination?
  - Exact size (px) and weight at this level

Important: Rank by dominance — not by size. A large but very thin element
may be LESS dominant than a smaller but heavier element below it.

**After completing Step 2:**
1. Update `{{lens_plan}}` — set Step 2 status to `complete`, append findings to Step 2 Notes
2. Update `{{lens_handoff}}` with step completion

## Step 3 — Weight Inversion Detection

Check for weight inversion: elements that are LARGE in size but LIGHT
in weight, or SMALL in size but HEAVY in weight.

This is a critical signal — weight inversion means the design is using
spatial dominance and scale to drive hierarchy rather than relying on
weight contrast. Note any inversions found.

Example: "52px / weight 200" is a weight inversion if body text is
"14px / weight 400" — the large number is thinner than the small label.

**After completing Step 3:**
1. Update `{{lens_plan}}` — set Step 3 status to `complete`, append findings to Step 3 Notes
2. Update `{{lens_handoff}}` with step completion

## Step 4 — Hierarchy Mechanism

Identify the PRIMARY mechanism that creates hierarchy in this design.
Choose the most accurate description:

  SCALE-DOMINANT    — size differences do most of the work
  WEIGHT-DOMINANT   — weight contrast does most of the work
  POSITION-DOMINANT — placement (top-left, isolation) does most of the work
  COLOR-DOMINANT    — color/contrast does most of the work
  COMBINED          — two or more mechanisms work together (describe which)

Then identify which mechanism is deliberately NOT used. For example:
"Color is never used as the primary hierarchy signal — it is only used
to reinforce hierarchy established by size and position."

**After completing Step 4:**
1. Update `{{lens_plan}}` — set Step 4 status to `complete`, append findings to Step 4 Notes
2. Update `{{lens_handoff}}` with step completion

## Step 5 — Drop Ratio Analysis

Calculate the ratio between adjacent hierarchy levels:
  Level 1 → Level 2: [size ratio] (e.g., 44px → 12px = 3.7x drop)
  Level 2 → Level 3: [size ratio]
  [continue for all adjacent levels]

Note whether drops are: SHARP (>3x) / GRADUAL (<1.5x) / ABSENT (same size)

A sharp drop means the design uses distinct scale jumps with no in-between
sizes. A gradual drop means the scale flows continuously.

**After completing Step 5:**
1. Update `{{lens_plan}}` — set Step 5 status to `complete`, append findings to Step 5 Notes
