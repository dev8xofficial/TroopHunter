# Glossary

> Canonical vocabulary for the Dev8X platform. All spec-kit artifacts must use these terms consistently.

---

## Platform Terms

| Term | Definition |
|------|-----------|
| **Dev8X** | The unified talent management and client services platform |
| **Portal** | A role-scoped web application providing domain-specific functionality |
| **Module** | A self-contained functional unit represented by a numbered directory with 13 artifacts |
| **Domain** | A group of related modules sharing a numeric prefix (e.g., 1xx = HR Admin) |
| **Spec-Kit** | This repository — the complete set of functional specifications |
| **Constitution** | The foundational governance document defining platform principles, roles, and lifecycles |
| **ADR** | Architecture Decision Record — a documented architectural decision with context and rationale |

## Identity & Access

| Term | Definition |
|------|-----------|
| **Actor** | Any entity (human or system) that interacts with the platform |
| **Role** | A named set of permissions assigned to a user: `super_admin`, `hr_admin`, `candidate`, `client`, `sales_rep`, `manager` |
| **RBAC** | Role-Based Access Control — permission enforcement based on assigned role |
| **Session** | An authenticated user context with a JWT token, portal scope, and expiry |
| **MFA** | Multi-Factor Authentication — a secondary verification step (currently TOTP for Admin) |
| **TOTP** | Time-based One-Time Password — a 6-digit code generated by an authenticator app |
| **SSO** | Single Sign-On — authentication via external identity provider (Google OAuth 2.0) |
| **Portal Routing** | The mechanism that maps a user's role to their designated portal after authentication |

## HR / Talent Management

| Term | Definition |
|------|-----------|
| **Applicant** | A person who has submitted a job application through the Candidate Portal |
| **Candidate** | An applicant who is actively progressing through the hiring pipeline |
| **Pipeline** | The ordered sequence of stages an applicant passes through: Applied → Shortlisted → Interview → Selected → Joined |
| **Kanban Board** | A visual representation of pipeline stages as columns with candidate cards |
| **Stage Transition** | The act of moving an applicant from one pipeline stage to another |
| **Funnel** | A statistical view of pipeline conversion rates across stages |
| **Evaluation** | A structured scoring assessment of a candidate by an interviewer or hiring manager |
| **Time-to-Hire** | The average duration from application submission to job offer acceptance |
| **Source** | The origin channel of an applicant (e.g., LinkedIn, Referral, Website) |
| **Future Hire** | A rejected candidate marked for reconsideration in future openings |

## Client Services

| Term | Definition |
|------|-----------|
| **Project** | A client engagement with defined scope, team, budget, and timeline |
| **Invoice** | A billing document for services rendered, with line items and payment status |
| **Time Entry** | A logged work session with date, hours, task description, and team member |
| **Budget Burn** | The percentage of allocated budget consumed by logged time entries |
| **Working Hours** | Aggregated time tracking data, typically from Clockify integration |
| **Support Ticket** | A client-raised issue or request tracked through resolution |
| **Contract** | A legal agreement between Dev8X and a client, requiring e-signature |
| **Payment Type** | The billing model for a project: Fixed, Hourly, or Monthly |

## CRM / Sales

| Term | Definition |
|------|-----------|
| **Contact** | A person or organization tracked in the CRM system |
| **Lead** | A contact identified as a potential business opportunity |
| **Deal** | A tracked business opportunity with a dollar value moving through the sales pipeline |
| **Lead Temperature** | A qualitative score: Hot (active engagement), Warm (some response), Cool (no response) |
| **Lead Score** | A 0–100 composite score based on: Response Time, Budget Fit, Decision Power, Timeline, Tech Stack Match |
| **Health Score** | A 0–100 metric indicating overall contact relationship quality |
| **Sentiment** | The current relationship status: Positive, Neutral, Negative, No Response, Burned |
| **Decision Maker** | A contact flagged as having purchasing authority |
| **Lead Stack** | A curated list of leads grouped by criteria (e.g., "SaaS Founders Series A+") |
| **Outreach** | A communication attempt to a contact via any channel |
| **Channel** | A communication platform: LinkedIn, Email, WhatsApp, Upwork, Cold Call |
| **Template** | A reusable message body with variable placeholders for outreach |
| **Stale Deal** | A deal that has not progressed for a defined period (amber: warning, red: critical) |
| **Heatmap** | A day-of-week × time-of-day matrix showing optimal outreach response windows |
| **Conversion Rate** | The percentage of leads that progress from one pipeline stage to the next |

## Document Management

| Term | Definition |
|------|-----------|
| **E-Signature** | Electronic document signing with timestamp and identity verification |
| **Document Category** | A classification group: Employment Docs, Identity Verification, Tax & Compliance, Education, Contracts, Deliverables, Reports |
| **Document Status** | Current state: Pending (awaiting action), Signed (completed), Draft (not yet issued) |

## System

| Term | Definition |
|------|-----------|
| **Activity Log** | An append-only audit trail of all system events |
| **Event** | A recorded system action with actor, timestamp, entity, and action type |
| **State Machine** | A formal definition of an entity's lifecycle states and valid transitions |
| **Validation Schema** | A JSON Schema defining payload structure, types, and constraints |
| **API Contract** | A formal REST endpoint definition with request/response structure and error codes |
| **Feature Flag** | A toggleable switch controlling the availability of a feature at runtime |
| **Guardrail** | A negative constraint defining what the system must never do |
