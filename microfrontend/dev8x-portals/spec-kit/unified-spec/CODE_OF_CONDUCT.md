# Code of Conduct

> Community standards for contributors to the Dev8X Unified Spec-Kit.

---

## Our Standards

Contributors are expected to:

- **Be respectful**: Treat all participants with dignity and respect
- **Be constructive**: Provide actionable feedback with rationale
- **Be precise**: Use the canonical vocabulary defined in [GLOSSARY.md](GLOSSARY.md)
- **Be thorough**: Follow the 13-artifact module standard without shortcuts
- **Be collaborative**: Seek consensus on cross-domain changes

---

## Unacceptable Behavior

- Introducing UI/design content into functional specifications
- Duplicating content that should be referenced from centralized contracts
- Bypassing CI validation checks
- Modifying historical changelog or ADR entries
- Using technology-specific language in spec files

---

## Enforcement

Violations are addressed through the [governance escalation path](GOVERNANCE.md):

1. **Warning**: First occurrence — contributor notified
2. **Correction**: PR rejected with required changes
3. **Restriction**: Repeated violations — review access revoked temporarily
